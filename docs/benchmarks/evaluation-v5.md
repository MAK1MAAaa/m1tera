# v0.5 Harness 评测

日期：2026-10-13。模型：官方 ChatGPT 连接的 `gpt-6.1-sol`。本轮完成用户独立 OAuth 授权，真实账号目录包含 7 个可见模型，sol 的可信上下文上限为 500,000 tokens；未读取既有 Codex 凭据。

当前实现能运行公开单轮评测，并在固定日志样本上减少上下文输入；持久恢复和工具副作用边界由故障注入及包内 smoke 验证。下面的成绩不能概括完整、多轮个人 Agent 能力。

## 真实模型结果

| 固定子集 | 正确 / 已判分 | 错误 | 未作答 | 未知 | 准确率 | 输入 usage | 耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| BFCL v4，10 simple_python + 10 multiple | 18 / 20 | 2 | 0 | 0 | 90% | 3,407 tokens | 93.814 秒 |
| SimpleQA，官方 seed=0 抽样 20 题 | 16 / 20 | 3 | 1 | 0 | 80% | 28,673 tokens | 292.676 秒 |

共 60 次真实请求：BFCL 20 次，SimpleQA 作答 20 次及评分 20 次。总输入 usage 为 **32,080 tokens**，包含缓存输入；SimpleQA 的 usage 包含 grader 请求。其作答尝试后的准确率为 16/19，即 **84.21%**；主准确率仍以全部 20 道已判分题为分母。

每题使用独立空历史及当前运行时的同一 harness factory。BFCL 工具仅记录调用，不产生外部副作用；本地 TypeScript AST 规则移植先通过 60 份离线官方规则对照，本次保存的真实预测又由 SHA 锁定、未修改的官方 Python scorer 再评分，**20/20 逐题判定一致**。SimpleQA 不使用浏览，标准答案只进入另次独立 A/B/C grader 请求，不进入作答请求。

这两套是固定 20 题单轮子集，不对标完整官方榜单，也没有测量规划、多轮工具执行、长任务或持久恢复的模型表现。SimpleQA 作答与 grader 使用同一模型，存在评分偏差；未进行独立模型或人工复核。没有为本次失败调整提示词、改参考答案或放宽评分。

证据：[BFCL 原始结果](bfcl-v4-gpt-6.1-sol-live.json)、[官方 scorer 核验](bfcl-v4-official-check.json)、[SimpleQA 原始结果](simpleqa-gpt-6.1-sol-live.json)、[数据版本、抽样与许可](../../benchmarks/README.md)。

## BFCL 失败边界

simple_python 为 10/10，multiple 为 8/10。

| 题目 | 预测与失败原因 | 可采取的改进 |
| --- | --- | --- |
| multiple_3 | 函数与坐标正确，但指定 `rounding: 4`；文档默认 0，参考允许省略或 0。 | 在未参与评测的工具任务中检查默认参数遵从，避免擅自改变可选参数。 |
| multiple_7 | 调用了增长与生态影响两个函数，官方单函数类别参考仅接受增长函数，触发 wrong_count。 | 在新任务中区分用户多意图与评测类别约束；不据此把通用助手统一限制为一次调用。 |

第二题原文同时提到增长及林地影响，具有评测边界；本次严格保留官方失败，不将其解读为实际个人助手的两工具策略必然无效。详细预测见 [失败分析](bfcl-v4-failure-analysis.md)。

## 上下文与恢复验证

使用真实 harness factory、Pi 请求格式化/SSE 解析及工作区工具，provider 为进程内 fixture。相同 **35,177 字节**合成日志原文模式发起 2 次请求、外置模式发起 3 次请求；后者包含取回中部页和新增 schema。

| 指标 | 原文模式 | 外置模式 |
| --- | ---: | ---: |
| 累计输入本地估算 | 11,873 tokens | 2,369 tokens |
| 命令执行次数 | 1 | 1 |

单一样本累计输入估算减少 **80.05%**。完整原文 SHA256 相同，1536 字符中部页正确；请求增加而输入减少，体现结果外置与按需取回的权衡。provider 是 fixture，读取位置由脚本选择，数值不是实际模型 usage，也不证明模型能正确检索或理解任意外置结果。见 [可复现管线报告](harness-local.md)。

运行时与包内检查覆盖轮次暂停、Unicode 分页、引用隔离、提交去重和保存失败：intent 保存失败时执行 0 次写入；outcome 保存失败时已发生 1 次写入、自动重放 0 次，结果保持未知。恢复失效旧审批，写入与命令重新逐次批准。这些机制不承诺任意命令 exactly-once、原流恢复或断电耐久。

当前 **299 项自动化检查**（255 runtime、33 E2E、11 Rust）及 **11 项包内 smoke**通过；检查范围与原文链接见 [v0.5 验证记录](../validation-v5.md)。独立视觉、其他平台安装和独立无 Node 机器安装仍未验收；真实账号原生 web search 也未验证。

## 后续评测优先级

1. 用新的、未参与本轮评测的工具任务检查默认参数和多意图调用；保持当前样本、提示词与评分证据，避免对固定题过拟合。
2. 以独立 grader 或人工抽查复核 SimpleQA 错误与未作答，再扩大固定样本或执行重复运行，衡量稳定性与评分偏差。
3. 增加真实模型多轮任务，要求模型自行定位外置结果页，比较完成率、累计实际输入、请求次数和耗时；当前 fixture 的 80.05% 不能代替这项实验。
4. 对真实模型任务施加中断、拒绝审批及 outcome 保存故障，验证恢复后的任务完成与副作用核查；保留未知状态，不以重放消除未知。

这些是后续改进的验证计划，本轮尚未执行，也没有据当前小样本预设硬 token 上限或引入自动摘要。
