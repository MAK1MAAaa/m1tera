## 模型目录与启用

官方设置始终保留 Continue with ChatGPT，连接与模型勾选互不替代。官方目录使用同一账号的 OAuth Bearer 请求 `/v1/models`，解析 `models[].slug`、`display_name` 和 `visibility`，仅接受 `visibility = list` 并保留服务端顺序。测试核验请求协议、动态新模型、空目录、取消、换账号时旧响应隔离和刷新失败；不再将 Pi 的全部静态模型当成账号可用目录。依据为 [官方模型与推理文档](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)。

自定义接口使用 `/models` 的 `data[].id`，也允许手动填写模型 ID、名称和上下文上限。新发现模型默认未勾选；输入框只显示已勾选且未明确不可用的项。界面和运行时均拒绝未启用模型，原始 RPC 与基线测量也不能绕过检查。停用当前项、移除模型或删除当前接口后，保留待重选状态，不自动切换或重建已删除接口。

目录中的明确停用、弃用、不可用和 shutdown_date 会影响可选状态。未来停用日期使用“计划停用”文案；不因 created 时间早就判定退役。媒体或 embedding 专用模型不列为聊天候选。未知的手动 ID 保留为未验证；手动添加不能覆盖目录明确的停用结论。依据为 [OpenAI 弃用说明](https://developers.openai.com/api/docs/deprecations)；多接口配置参考 [OpenCode providers](https://opencode.ai/docs/providers/)。服务商不提供生命周期元数据时，无法单凭模型名称可靠判断是否下架。

成功的完整目录不再包含某个旧目录模型时，该模型标为不可用；显式手动模型保留用户意图并标为未验证。失败刷新保留已知名称和容量，将原可用状态降为未验证并显示警告，已有不可用状态不会被失败刷新恢复。单次目录响应限制为 1 MiB，读取与请求均有 4 秒边界；目录不按 256 条截断，260 条目录的末尾模型仍能查找与选择。每个接口可保存的模型配置上限仍为 256。

## 接口、凭据与缓存

各接口有独立 ID、base URL、API 格式、启用项和内存密钥。同 URL、同模型 ID 的两个接口使用不同 key 与容量的测试通过，目录上限不会跨接口串用。更换 base URL 或删除接口会清除旧 key；同 URL 切换 API 格式保留 key。留空保留已有 key，显式清除只影响对应接口。目录请求禁止重定向携带授权；错误不回显响应正文、地址或密钥。

配置持久化仅包含接口信息、模型 ID / source / enabled，以及用户手工指定的名称和容量。API key、OAuth 凭据、实时目录与候选指纹只在内存中。退出后需重新连接并刷新目录，自动发现的元数据不会被永久写成用户覆盖值。

保存新接口前取得的候选，仅在接口 ID、规范化 URL 与密钥指纹一致时归入本次运行的目录；保存后仍可保留动态名称和容量。密钥从 A 改为 B 再改回 A 的竞态、失败缓存降级和成功刷新缺少容量字段的清理均有回归覆盖。未知容量保持未知，不沿用过时字段或为新模型猜测数值。

独立安装包 smoke 使用 `Contents/MacOS/node` 启动 `Contents/Resources/resources/runtime/index.js --data-dir <临时目录>`，完成一次本机 Chat Completions SSE 聊天，无外网请求。核验未连接的官方默认项、候选目录保存、停用和非文本过滤、未勾选模型的 run.start / 实测基线 RPC 拒绝、选定附件与工具的上下文、usage 缺失、手动容量和重启恢复。请求仅含所选的两项工具；JSONL、stderr 和持久化文件均没有测试 key，重启后配置与会话恢复但 key 不恢复。测试产生的 appData、工作区、sidecar 和模拟服务已清理。此检查不等同于在独立无 Node 机器上安装 app。

## 桌面和交付边界

最终 0.4.0 原生 app 已启动，恢复了 4 条旧会话和已有工作区。通过辅助功能树核验：设置包含官方登录、已勾选的 gpt-6.1-sol、添加自定义接口、base URL / API 格式 / 密钥输入和手动模型编辑。草稿中取消当前模型的勾选后出现重选提示。该检查未保存测试接口或密钥，未发起真实模型请求。随后 Mac 锁屏，阻止继续操作和关闭该未保存草稿；它不代表持久化配置已被修改。

独立视觉复核另行交付；自动化布局检查与辅助功能检查不能替代视觉结论。当前新的官方 OAuth 目录发现尚未使用真实账号验收；测试不会读取 Codex / ChatGPT 已有凭据。自定义接口使用本地模拟响应，外部服务商的实际推理仍需用户提供接口后验证。

## 独立视觉复核（2026-10-12）

独立验证器已检查真实 React/CSS 的 1280×850 和 800×600 浅色/深色，共 35 张明确标注隔离 fixture 的截图。四个常规布局用例通过：文档不滚动，设置页脚固定，长目录内部滚动，手工编辑可用，跨接口同名模型可辨，当前模型失效后显示重选提示。两个补充边界用例失败，且截图确认了目录刷新失败后的状态标签问题；因此尚未通过完整视觉验收。

确认的待修复项为：800×600 下四个接口目录警告使 picker 顶部 y=-104.69px、搜索入口被裁切；同一设置草稿成功拉取后再失败，模型仍显示“目录已验证”；合法 100 字符接口名使当前模型摘要和删除标题横向溢出。验证状态文字还存在 10px、偏淡的可读性偏差。复现、精确几何和截图见 [独立视觉报告](visual-verification-v4.md)。该结论不撤销前述 runtime/安装包自动化结果，但补充了自动化回归未覆盖的界面问题。

本轮没有读取真实账号或密钥，没有写入用户数据，也没有联系真实接口。Mac 锁屏，原生 app 的本轮视觉复核及此前未保存设置草稿的取消均未执行；浏览器 fixture 不能作为原生或真实账号验收。
