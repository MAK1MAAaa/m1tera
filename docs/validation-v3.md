原生应用实际启动后恢复了 4 条旧会话及已有工作区。Skills 管理展示三项内置技能，自动匹配默认关闭。原生输入框通过 `$` 选中 writing、`@` 选中工作区 `hello.txt`，粘贴 `/plan` 后显示结构化命令和引用标签；预计输入由 40 增至 204 tokens，上限为当前固定目录的 272,000。清空草稿后恢复 40 tokens，实际 usage 仍显示“未知”。上述操作没有调用真实模型，也没有写入工作区文件。

原生测试初次读取 Desktop 目录时，macOS 等待文件夹授权，导致 30 秒 IPC 超时。系统授权完成后重试，文件候选与读取均成功；线程调用栈和系统日志确认等待发生在系统文件访问处。未绕过或修改系统隐私权限。开发构建的签名变化可能使 macOS 再次请求文件夹授权。

搜索有两条运行路径。ChatGPT 与 `api.openai.com` 的 Responses 连接注入原生 `web_search`；其余兼容接口添加客户端搜索工具。原生搜索通过本地 Responses SSE 验证了实际 schema/tool_choice/include、UTF-8/CRLF 分片、事件、来源去重、安全链接、取消和缺少搜索事件的错误。搜索工具的 128k 有效上限单独显示，普通聊天不会继承该工具限制。真实 ChatGPT 账号原生搜索权限尚未验证。

客户端 DuckDuckGo 搜索已使用应用相同的系统代理配置完成真实公开检索：查询 `Tauri 2 official documentation`，返回 6 条结果，包括 `https://v2.tauri.app/` 和官方文档仓库。这验证了客户端检索与解析，不代表真实模型已经在一轮对话中调用搜索。此前不使用代理的连接超时保留为网络诊断事实。

上下文控制已核验：显式 `$` 指令只进入选用当轮系统提示词；自动选择默认关闭，启用后模型先获得简短目录和关键词，再通过 `use_skill` 加载正文。当前轮内部工具链保留正文，下一轮旧的 `use_skill` 结果压为短标记，保留合法调用与结果配对；关闭自动选择或停用技能不会重新注入旧指令。附件正文属于显式会话历史，后续会保留；文件候选目录和组织元数据不进入请求。

独立代码复核发现的模型上限缓存、跨会话估算、旧 Skill 指令及取消状态问题均已修复并补回归。独立视觉复核另行运行，自动化布局检查和原生功能检查不能替代其结果。[暗色界面截图](screenshots/desktop-dark-model-picker-fixture.png)使用真实 React/CSS 与隔离测试 fixture。

本轮没有重测真实模型 token 基线；0.1.0 的 49 / 237 / 957 输入结果仅作历史记录，见 [基线报告](context-baseline-live.md)。API key/OAuth 凭据仍只在后端内存，升级或退出后需要重新登录。

其他操作系统的安装产物、独立无 Node 机器安装、公开签名与公证仍未验收。安装包约 63.76 MiB，app 约 217.56 MiB；精确大小、SHA256 和内置依赖 lockfile 一致性见 [产物清单](release-artifacts.json)。历史产物清单保留为 [0.2.0](release-artifacts-0.2.0.json) 和 [0.1.0](release-artifacts-0.1.0.json)。
