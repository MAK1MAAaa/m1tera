# m1tera 桌面设计规范

用于 `src/**` 的 React 界面与后续交互设计；`opendesign/mockups/desktop-v2/` 保留为 v0.2 历史参考，不能作为 v0.3/v0.4 行为或实测依据。先加载 `tokens/colors_and_type.css`；它是 m1tera 自有的规范，不是 Codex 官方样式或 token。

## 方向与来源

用户明确要求参考 Codex 的桌面工作方式：工作区驱动的左侧导航、安静的居中聊天、composer 模型/审批选择、可折叠上下文。已有产品的真实来源是 `src/App.tsx`、`src/App.css`、`src/index.css`、`src/components/SettingsDialog.tsx`、`src/components/ApprovalDialog.tsx`、`src/components/BaselinePanel.tsx`。沿用已有 `m1tera` 和 `m` 标识、中文产品文案、lucide-react 图标体系。新版工作区与组织操作是用户授权的新增设计，不能把它们描述为原有组件。

## 窗口与层级

- `html`、`body`、`#root` 与应用框架占满窗口，`overflow: hidden`，布局子项设置 `min-width: 0`、`min-height: 0`。
- 不通过 `scrollIntoView()` 移动外层窗口；消息滚动操作只改变聊天容器的 `scrollTop`。
- 左侧导航约 252px，可独立滚动会话列表。顶栏、底部设置固定。
- 中间聊天内容最大宽度约 760px；顶部约 60px，底部 composer 固定在聊天面板内部。
- 右侧上下文约 276px，可关闭；内部独立滚动，不强迫所有用户始终看诊断数据。
- 小窗口先收起上下文，侧栏可通过按钮显式收起；不能用最小高度把整个文档撑出窗口。

## 色彩、字体与密度

中性白色聊天区、浅灰侧栏、深灰正文。绿色只用于已连接/已完成；黄色只用于自动审批提醒；红色只用于失败/删除。禁止大面积渐变、营销装饰、彩色边条卡片。

沿用已有 DM Sans + 中文系统字族，无需外部字体网络。正文 14–15px，导航 13px，辅助文字 11–12px；正文行高 1.75，控件行高 1.4。中文标题使用正常字距；路径、token 计数和代码使用等宽字族及 tabular-nums。

4px 空间基线；控件内间距 8–12px，区域间 20–24px。一般控件圆角 8px、弹层 12px、composer 20px。主按钮深灰白字，常规操作透明/浅灰。阴影仅用于浮层；悬停背景轻微变深，按下略微加深。状态切换 120–180ms，遵循 reduced-motion。

## 行为与语义

- 会话菜单包含改名、置顶/取消置顶、分类/移动工作区；删除需清晰确认。
- 工作区是用户选定目录的组织单位，展示短名与可查看完整路径。选择目录不会自动读取文件、指令或记忆。
- 模型目录、登录和勾选启用是独立状态；输入框只展示已启用且未标为不可用的模型。目录发现不保证推理请求成功。切换只影响下一次请求。
- 自动审批是用户明确选定的权限策略，和工具是否启用分开。未启用工具始终不发送 schema、不执行；不得为自动审批新增系统提示词。
- “轻量”指模型上下文：保留 0 工具默认、显式上下文来源、usage 未知状态，不为了界面体积阉割产品。
- 未返回 usage 显示“未知”，估算和实测分开展示，缓存仍计入上下文。

## v0.4 模型配置与目录

- 官方 ChatGPT OAuth 面板始终可见，包含登录、取消登录和注销入口；选择自定义接口不能将它隐藏。登录凭据只在本次运行保留，不读取既有 Codex/ChatGPT 凭据。
- 官方目录只请求当前账号的 `GET https://api.openai.com/v1/models`，使用 OAuth Bearer，解析 `models[]` 的 `slug`、`display_name`、`visibility`，只保留 `visibility = list` 的候选与服务端顺序。不展示全 Pi 静态目录。未登录或请求失败时，仅显示显式 `gpt-6.1-sol` 默认项或同账号最近缓存，标为未验证并显示警告，不暗示账号已有使用权限。
- 自定义接口按其 `/models` 的 `data[].id` 发现候选，读取名称、上下文容量与明确的 `lifecycle`、`deprecated`、`shutdown_date` 等状态，不用 `created` 日期猜测退役。已停用、已弃用和明确计划停用均不可启用；未来停用日期使用“计划停用”，不能写为已经下架。
- 模型勾选状态与发现结果、账号连接分开。新发现模型默认不勾选，手动新增默认不启用；用户勾选并保存后才进入 composer。运行时同样拒绝未启用或明确不可用的模型。
- 自定义接口分别提供名称、base URL、API key、Responses/Chat Completions 格式和模型配置。手动模型提供 ID、可选显示名称和上下文上限；允许网关未列出的 ID，明确标为未验证，容量未知保持未知。目录明确的停用状态不能通过手动添加绕过。
- 最多保存 12 个自定义接口，每个接口最多保存 256 个模型配置。目录发现不按合法条目数截断；单次目录响应限制为 1 MiB。模型列表独立滚动，长目录不能撑出窗口。
- 同名模型展示服务商名称，并按服务商区分选中状态；上下文容量缓存按服务商隔离。停用或移除当前模型、删除当前接口时，保留选择为待重选状态，提示用户显式选择其他已启用模型，不自动 fallback。
- 刷新失败保留已知名称和容量，原可用状态降为未验证并附警告；已明确不可用的状态不能因失败变成可用。成功完整目录缺少旧接口发现项时，将其标为不可用；缺少手动项时，保留用户显式意图并保持未验证。
- 持久化服务商名称/base URL/API 格式，以及模型 ID、来源、启用状态和用户手工指定的名称/上下文上限；旧版单接口设置迁移为 `custom-default`。实时目录名称、容量和可用性仅保留在内存；退出后需重连账号或配置 key 并重新拉取。不把完整目录自动复制为永久覆盖值而遮蔽以后刷新出的新容量。配置与目录元数据不进入模型上下文。
- API key 按服务商隔离且仅在内存保存。输入框留空保留现有 key，独立“清除本接口的现有密钥”复选框表示显式清除。修改 base URL 或删除接口清除该接口 key，不隐式将旧 key 带到新地址；同 URL 下修改 API 格式保留 key。
- 新接口保存前的候选发现只在内存保留 URL 与密钥的 SHA256 指纹；保存时仅在 URL/key 匹配后归入该接口的本次运行目录，避免同一次运行保存后丢失发现结果。目录候选、原密钥与指纹均不持久化，不跨重启保留，接口之间不复用凭据。

协议与来源：[OpenAI 模型与推理](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)、[OpenAI 弃用说明](https://developers.openai.com/api/docs/deprecations)、[OpenCode providers](https://opencode.ai/docs/providers/)。这些来源提供协议与参考，不作为本项目真实账号验收结果。

## Composer 与按需上下文

- `/` 候选只在消息开头触发；正文中的路径保持普通文本。`@`、`$` 仅识别光标前的独立输入片段，不将邮箱识别为文件触发器。候选支持方向键、Enter 与 Escape，滚动仅发生在候选列表。
- 选中的命令、文件与 Skills 显示为带文字和移除按钮的标签。移除即取消本轮引用；发送成功后清空该次草稿，失败保留待重试内容。
- `/plan` 为本轮只读计划模式，明确目标、步骤、验证和依赖；只保留已启用的读文件、列目录工具，不提供写文件或终端命令。
- `/websearch` 必须实际联网搜索并给出可核验来源和 citations。ChatGPT 和 OpenAI 官方 Responses 连接使用原生 web search，其余兼容接口使用网页搜索工具。展示搜索执行状态与来源链接；检索失败或缺少可核验搜索事件时明确失败，不将模型自行生成的文字视为已检索结果。
- `/new` 新建会话；`/clear` 清空草稿及本轮命令、文件、Skills；`/skills` 打开技能管理。三个管理命令不发送模型请求。
- `@` 按需查询当前工作区文件；没有工作区时给出明确的选择提示。发送时读取已选文件正文，作为数据加入本轮请求。文件引用不得自动发现或注入项目指令、记忆、其他文件。
- `$` 只列出已启用且本轮尚未选中的 Skills。手动选择的 Skills 仅按需加入本轮指令；启用某项技能不等于每轮加载它。

## 上下文圆环与详情

- 圆环使用本轮发送前的实际本地预计输入：提示词、草稿与历史、已选文件与 Skills、工具定义。不得用演示值、上一轮 usage 或固定百分比替代。
- 分母使用可信模型目录或用户显式配置的上下文上限；切换模型或修改提示词不清空已取得的目录上限缓存，并按当前模型取值。未知上限保留“未知”和 `?` 状态，不猜测模型容量或占比。ChatGPT 原生 web search 请求按可信模型上限与 128,000 tokens 中的较小值显示有效上限；模型上限未知时仍显示未知。
- 悬停显示预计输入、可用上限与“本地估算”；点击打开可折叠详情。圆环、文字说明与键盘入口共同表达状态，接近或达到上限时给出可辨识提示。
- 详情分开显示预计输入和“本次首轮实际输入”。Skills 计数是系统提示词的子项，文件计数是消息与历史的子项，不重复累计。未提供或全零 usage 保留未知，缓存读取和写入计入实际输入。
- 当前没有硬 token 上限或自动摘要；不以圆环状态暗示已经完成自动裁剪。

## Skills 管理与自动匹配

- 创建和编辑自定义 Skill 提供名称、描述、匹配关键词和指令；导入只读取用户选定的 `SKILL.md`。技能库支持搜索、启用和停用；删除自定义 Skill 前显示名称和确认。内置 Skill 的指令只读，只允许启用或停用，不能编辑或删除。
- 会话自动匹配（`autoSkills`）默认关闭；关闭时不向模型发送整个技能目录或 `use_skill` schema。启用后仅发送已启用技能的简短目录与 `use_skill`，由模型根据任务调用后加载需要的指令，不预先注入所有技能内容。
- 自动加载的完整指令仅保留在本轮工具链；后续请求将历史 `use_skill` 结果压成短标记。关闭自动匹配或停用技能后，不得继续通过旧工具结果重新注入完整指令；压缩后的历史仍保留必要的调用语义。
- 手动选择与自动匹配清晰区分，展示实际调用的技能；二者都不授予额外的文件、终端或网络权限。文件与技能始终按需加载，不自动扫描项目发现规则。
- 账号 OAuth 凭据与 API key 只保存在后端内存；应用退出后需要重新登录或配置。界面不得暗示已持久保存凭据。

## 文案与图标

简体中文，短动作名：新会话、工作区、置顶、改名、分类、模型、逐次审批、自动审批。避免全大写英文装饰标题、emoji 或说明内部实现。用户做权限决定时给具体范围与效果。

实现继续使用真实 `lucide-react` 组件；不要手绘 SVG。参考 HTML 使用已有 `m` 标识和简短文字/基础字形控制，不声称复刻 Codex 图标资源。状态只靠色彩不够，同时给文字。

## 验证

独立验证器检查原生窗口与浏览器预览：body 无滚动、长聊天与长导航只滚动本区域、宽高变化不藏 composer、弹层可用 Escape 关闭、键盘焦点可见、模型/审批选项可操作。v0.3 还需检查候选键盘导航、标签移除、只读计划、搜索执行与来源、文件和 Skills 按需加载、未知上限与 usage、自动匹配默认关闭、内置技能只读与自定义技能管理。

v0.4 还需检查官方 OAuth 始终可见、目录顺序与状态、勾选和登录分离、多接口密钥与缓存隔离、手动未知模型、计划停用文案、目录失败保留元数据、当前选择失效后的重选提示、迁移和目录候选保存。新的官方 OAuth 模型发现尚未使用真实账号验收，当前协议与配置流程由 loopback/fixture 验证；不得读取既有凭据来补齐实测。

搜索协议与 citations 已通过 fixture 验证，DuckDuckGo 客户端搜索已使用应用相同的系统代理配置实测成功；真实 ChatGPT 账号原生搜索尚未验证，不得将 fixture 当作账户权限验证。参考 HTML 中的模拟数据必须显式标明，不能作为真实模型能力、usage 或网络验证。当前实际检查结果记录在 [v0.4 验证记录](../../../docs/validation-v4.md)；保留 [v0.3](../../../docs/validation-v3.md)、[v0.2](../../../docs/validation-v2.md) 与 [v0.1](../../../docs/validation.md) 历史记录并明确其适用版本。
